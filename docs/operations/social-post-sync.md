## 运行规则

- 仅 `postSyncMode=verified`、`postMonitoring=true`、总状态启用的来源进入新增逐条同步；旧的 agent-sync 路径排除这些来源，避免两条调度重复发送。其他来源的行为不变。该模式目前用于精确绑定的 Discord 频道。
- 复用现有生产分发 worker，每 5 分钟检查。首次成功检查为每个账号及目标建立同步起点，不补发历史内容。新增目标单独建立起点，不向新频道倾倒旧内容。
- X 优先官方时间线，排除回复与转发，读取当前返回的最多 100 条原创内容。现有 Key 无读取额度时使用原有公开 Reader 路径，并校验推文链接归属、从编号解析时间。公开页有缓存和可见条目限制，可能延迟或遗漏；状态中明确显示降级，不能承诺完整或实时的 X 同步。没有自动购买额度，也没有向公开 Reader 发送 API Token。
- YouTube 使用频道官方 uploads 列表获取最近最多 50 个候选，再通过 videos.list 验证归属、发布时间和类型。预约、正在直播及带直播详情的回放不进入普通视频同步，避免重复通知。普通上传视频及 Shorts 可进入同步。
- 每条内容及精确目标分别保存永久回执，标识不含标题，编辑标题、重复检查、来源别名和重启不会重发。同一轮读取到的多条新内容分别处理。
- 发送前持久占位；返回真实 Discord 消息编号后才确认成功。超时或回执保存不明确保持待核对，不自动重发，普通失败重试入口也禁止重放此类历史通知。
- 每次发送使用英文卡片：主播、标题、发布时间、观看或阅读链接。非拉丁文字使用英文通用标题，不编造翻译。关闭自动提及，不改变原频道权限和机器人身份。
- 总暂停和普通帖子关闭均停止普通同步；保存期间账号、开关或目标发生变化时，当前检查停止投递。

## 运维验收

先部署代码，再通过已鉴权的 `social-packages` 的 `action=test` 只读验证带 `postSyncMode=verified` 的两条来源，最后逐条 upsert 启用。已有 YouTube 来源仅开启普通更新并增加模式字段，直播配置不变；新增 X 来源绑定同一唯一 Discord 目标，`liveMonitoring=false`。

`GET /api/social-posts` 提供最近实际检查、同步起点、发现数量、跳过的直播数量及投递状态，管理员页面展示这些信息。匿名及手动发布角色不能访问。检查正式 SHA、来源配置、历史回执与实际 worker 时间，不能用本地模拟发送冒充真实外发。
